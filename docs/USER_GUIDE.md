# 操作ガイド

## 言語を切り替える

画面右上の「Language」から **日本語 / English / ไทย** を選べます。このラベルは、選択した言語にかかわらず英語で表示します。操作画面、全ケースの設問・ヒント・前提説明・詳細解説、仮想READMEの説明が切り替わります。コマンド構文・調査対象のログ・正解の値は共通です。元のツールの構文ヘルプと外部の参考資料は、各資料の言語で表示されます。

言語を切り替えても、ケース、解答、正解状況、メモ、作成ファイル、コマンド履歴、画面設定、入力中のコマンドは保持します。言語の選択も同じlocalStorageに保存されます。ケースの初期化や画面設定のリセットをしても言語は変わりません。

利用者が書いたメモやファイル、すでに実行したコマンドの出力は自動翻訳しません。viやページャーを開いている場合は、閉じてから言語を選びます。slとGAME OVERの演出中は切り替えを待ってください。

[READMEに戻る](../README.md) · [演習を開く](../index.html) · [コマンド一覧](COMMANDS.md)

## 起動する

ダウンロードした `index.html` をブラウザで開きます。インストール、管理者権限、Linux環境、アカウント登録は不要です。ブラウザでJavaScriptが許可されている必要があります。

組織の設定でローカルHTMLを開けない場合は、許可されたWebサイトに配置した版を利用してください。組織の制限を解除する操作は教材の対象に含まれません。

## 演習の進め方

1. **ケースを選ぶ**。画面が狭い場合は選択リストを使います。
2. **前提・構成を読む**。状況、調査目的、サーバーの役割、ログの種類、正常時の動作を確認します。
3. **正常ログを観察する**。最初は正常時のログです。`cat /home/analyst/README.txt` で対象ファイルを確認できます。
4. **攻撃ログを生成する**。用意した攻撃イベントをログへ反映します。外部への通信や実際の攻撃は発生しません。
5. **コマンドで調べる**。検索・集計・時系列・複数ログの一致を根拠にして解答します。
6. **解答を確認する**。必要に応じて段階的なヒントや、根拠ログ、調査の進め方を参照します。
7. **全問正解後の解説を読む**。各ケースの技術知識、攻撃の流れ、対策、観測できる範囲、歴史的な事案、参考資料を確認します。

解説の解放条件は、そのケースに攻撃ログを反映し、すべての設問に正解していることです。解答を変更して不正解にすると再び解放待ちになります。ケースを切り替えても、各ケースの進捗は保持されます。

### 正常時と比較する

正常ログのコピーは `/baseline/var/log/` 以下にあります。元のパスの前に `/baseline` を付けて比較できます。

```sh
diff -u /baseline/var/log/auth.log /var/log/auth.log
```

この例はSSHケースで使えます。ケースごとに用意されるログが異なるため、先にREADMEや「前提・構成」でパスを確認してください。

「攻撃ログを生成」はケースごとに一度だけ反映できます。繰り返す場合は「サラの状態に戻す」を使います。生成時は演習ログを攻撃後の状態に切り替え、別途作成したメモファイルなどは保持します。

### 調査で意識すること

- 時刻はログごとに確認します。Webケースのnginxは **JST（+0900）**、アプリ監査は **UTC（Z）** です。同じ瞬間は9時間違って表示されるので、照合時はUTCにそろえます。年・TZがないSSH syslogはREADMEの2026年・UTCという採取条件で補います。
- HTTP 200、アプリの成功記録、プロセスの起動記録は、それぞれ示す事実が異なります。
- `request_id`、`query_id`、`pid`、`ppid`、メールのキューIDなどで、別のログの同じ処理を照合します。
- 同じイベントのテキスト版とJSONL版は二重に数えません。
- 観測した事実、そこからの推測、まだ確認できない点を分けてメモします。

## ターミナルの操作

入力欄にコマンドを入力し、Enterか実行ボタンで実行します。画面上のコマンド例を押すと入力欄に入り、Enterを押すまで実行されません。

| 操作 | 動作 |
| --- | --- |
| ↑ / ↓ | 実行履歴をたどる |
| Tab | 対応コマンドや仮想パスを補完する |
| Ctrl+L / `clear` | 表示を消す。仮想ファイルや解答は保持する |
| Ctrl+C | 通常は入力中のコマンドを取り消す。`sl`は中断できない |
| `help` | コマンド一覧とシェルの対応構文を表示する |
| `help grep` / `grep --help` | 指定したコマンドの対応構文を表示する |

Tab補完は入力末尾・引用符の外側で使います。完全なLinux端末ではないため、任意のキーボード操作やシェルの機能には対応していません。

### 検索・集計・保存

```sh
grep -n 'Failed password' /var/log/auth.log
grep 'Failed password' /var/log/auth.log | wc -l
grep 'Failed password' /var/log/auth.log > /home/analyst/failed.txt
cat /home/analyst/failed.txt
```

`>` は仮想ファイルを上書きし、`>>` は追記します。`|` は前のコマンドの標準出力を次へ渡します。作成先の親ディレクトリは存在する必要があります。

終了コード1が常に入力エラーを示すわけではありません。`grep`は一致なし、`diff`は差分ありの場合にも1を返します。エラーの説明やコマンドの用途と合わせて読みます。

### 閲覧用のless・more

`less ファイル` または `more ファイル` で閲覧画面が開きます。`/` で検索入力、`n` / `N` で次 / 前の一致、`q` で閉じます。Space、PageDown、PageUpでスクロールできます。実際のless・moreの全操作には対応していません。

## コマンド一覧を使う

上部の **コマンド一覧** を押すと、61コマンドの用途・対応オプション・入力例を検索できます。右側の **コマンド手帳** にはケースに応じた使い方の例があります。

一般のLinux資料にあるすべてのオプションを利用できるわけではありません。最終的な対応範囲は、画面の一覧と `help コマンド名` で確認してください。

## viで編集する

```sh
vi /home/analyst/investigation.txt
```

既存の親ディレクトリ内に新しいバッファを開けます。新規ファイルは `:w` で保存した時点で作られます。`view ファイル` は既存ファイルを読み取り専用で開きます。

| 操作 | 動作 |
| --- | --- |
| `i` / `a` | カーソルの前 / 後から挿入する |
| `I` / `A` | 行頭の非空白位置 / 行末から挿入する |
| `o` / `O` | 下 / 上に行を開いて挿入する |
| Esc | 通常モードへ戻る |
| `h` `j` `k` `l` / 矢印 | カーソルを移動する |
| `w` `b` `e` | 単語単位で移動する |
| `0` `^` `$` | 行頭 / 最初の非空白 / 行末へ移動する |
| `gg` / `G` / `10G` | 先頭 / 最終行 / 指定行へ移動する |
| `x` / `dd` / `dw` | 文字 / 行 / 単語を削除する |
| `cc` / `cw` | 行 / 単語を変更する |
| `yy` / `p` / `P` | 行をコピー / 後ろへ貼り付け / 前へ貼り付けする |
| `u` / Ctrl+R | 元に戻す / やり直す |
| `/文字列` / `?文字列` | 前方 / 後方検索する |
| `n` / `N` | 検索を同方向 / 逆方向に繰り返す |
| `:set nu` / `:set nonu` | 行番号を表示 / 非表示にする |
| `:%s/元/先/g` | 全行で基本的な置換をする |
| `:w` / `:wq` | 保存する / 保存して閉じる |
| `:q` / `:q!` | 閉じる / 未保存の変更を破棄して閉じる |
| `:help` | 対応する操作を表示する |

通常モード、挿入、検索、基本的なexコマンドの部分実装です。ビジュアルモード、プラグイン、外部コマンドの実行などには対応していません。`vi`と`view`は単独で実行し、パイプ・リダイレクト・コマンド列に含めません。

## 画面の広さを変える

ターミナルの表示設定で幅と高さを調整できます。演習パネルを折りたたむとターミナルが横幅いっぱいになります。元に戻す操作と、レイアウトを標準に戻す操作もあります。幅が狭い画面では表示を自動調整します。

レイアウト設定はケース共通で保存され、ケースを初期化しても保持されます。

## 保存と書き出し

解答、判定、ヒントの参照状況、メモ、コマンド履歴、仮想ファイルの変更などは **localStorage** に自動保存します。Cookieやアカウントへのクラウド保存ではありません。フッターの保存状態を確認してください。

同じブラウザ・同じ表示先で再開するのが基本です。ローカルファイルでの保存範囲はブラウザの実装にも依存します。次の場合には進捗が引き継がれなかったり、保存が消えたりすることがあります。

- 別のブラウザ、別のプロファイル、別の端末で開く。
- ローカルファイルを別の場所へ移す、またはGitHub Pagesなど別のURLで開く。
- ブラウザのサイトデータを削除する。
- プライベート閲覧や、保存を禁止する設定で利用する。

「このタブ内のみ」「永続保存できません」と表示されている場合は、ページを閉じたあとに進捗が残ることを期待できません。

**メモ → 調査メモを書き出す**で、選択中のケースの調査メモ・解答・コマンド履歴をテキストとして保存できます。仮想ファイルや全ケースの進捗を復元するインポート機能はありません。

## 初期状態に戻す

**サラの状態に戻す**を押して確認すると、選択中のケースを正常ログへ戻します。そのケースの解答、メモ、履歴、仮想ファイルの変更・作成も初期化します。他ケースの進捗とレイアウトは保持します。

仮想ファイルを削除・編集して演習を続けられなくなった場合も、このボタンでやり直せます。

### おまけの演出

- `sl`：蒸気機関車が約5秒間通過します。Ctrl+CやEscで中断できず、終わるまで入力を待ちます。ファイルと進捗は保持します。オプションやパイプには対応していません。
- `rm -rf --no-preserve-root /`：Logroom内の仮想ターミナルでは、画面崩壊 → 赤い「GAME OVER」→ 暗転 → 初期状態への復帰という演出になります。**選択中のケースの解答・メモ・履歴・作成ファイルは消えます**。演出のスキップやEscを使っても初期化は行います。

ブラウザの「視差効果を減らす」などの設定に対応し、`sl`は静止表示、GAME OVERは動きを抑えた表示に切り替わります。これらの演出もPC上のファイルや実際のOSには触れません。

## 困ったとき

| 状況 | 確認すること |
| --- | --- |
| 設問に関係するイベントがない | 「攻撃ログを生成」を押したか確認する |
| `command not found` | 画面のコマンド一覧か `help` で対応コマンドを確認する |
| オプションや式がエラーになる | `help コマンド名` で部分実装の範囲を確認する |
| ログが増えない | 静的なスナップショットのため、`tail -f`の追従には対応していない |
| 編集したファイルが見つからない | 現在のケースと `pwd`、viで `:w` を実行したか確認する |
| 攻撃全体の解説が開けない | すべての設問が現在も正解になっているか確認する |
| 画面が動かない | `sl`の通過を待つ。閲覧画面やviが開いていれば閉じる |
| 外部資料が開かない | インターネット接続や組織のアクセス制限を確認する。演習はそのまま利用できる |


## 実践モード・提出・ダウンロード

「演習設定・ログの持ち出し」から入門／実践と任意のシードを選んで適用します。設定ごとに解答、ノート、履歴を保持します。シードで変わるのは文書用IPで、件数や時刻は共通です。同じシードで同じデータを再現できます。

実践モードは攻撃イベントを含むログから開始し、`/baseline`はありません。SSHは2万行以上になり、analystがadmに所属しないため認証ログに`sudo`が必要です。過去期間の`auth.log.1`と`auth.log.2.gz`を参考に、件数・送信元・認証成功を絞り込みます。過去ログは当日と内容が異なるため、そのままdiffするより集計を比較します。

SSHの追加実技では対象IPの全イベントを`/home/analyst/timeline.txt`に保存します。「提出ファイルを確認」は行の欠落・重複・順序・保存先を検査します。元の104問の達成条件は保ち、実技は追加練習として扱います。ログを読まずに答えだけ入力した場合も、根拠確認を促す案内が出ます。

「ログをダウンロード（tar）」は現在のログ、README、作成した調査ファイルを書き出します。`.gz`は実際にgzip圧縮されます。新しい作業フォルダに展開し、`var/log/auth.log`などの相対パスでWSL/Linuxから同じ操作を練習できます。展開手順はアーカイブの`HOWTO.txt`にも入っています。実サーバーの`/var/log`へ上書きしないでください。

## 導入と出口の確認（v0.3.0）

初回はケース0の6行ログから始まります。4問で対象選択、列数の異なる行からの抽出、集計、元の根拠行のファイル保存を練習します。提出はファイルの実際の内容を検査し、行の欠落・重複・順序違いを通しません。既に操作できる方は「SSHケースを選ぶ」またはケース一覧から自由に始められます。

各ケースの「演習前に読める基礎」と「前提・構成」は回答前から利用できます。一般原理は先に読み、事件固有の結果や詳しい解説は従来どおり解答後に振り返ります。

WebとDNS・プロキシ・メールには、通常設問とは別に出口演習があり、そのケースの通常設問を終えると資料が開きます。必要な根拠行をファイル名・行番号・引用で選び、支えられる事実、未確認事項、次の確認を提出します。短い引継ぎメモは自分で例と比較するための欄です。文章の意味を自動採点する機能ではなく、空欄でも構造化した回答の採点は変わりません。根拠をすべて選ぶ、別要求の行を混ぜる、未確認を断定する回答は不正解です。

既存104問のID・解答・完了条件は維持します。導入4問と出口2本は追加の達成として保存し、以前のケース完了を取り消しません。既存10ケースと出口2本の完了で卒業案内を表示します。pcaproom-easyは新しいタブで開く任意のおすすめです。このroom内の復習・実践を続けられ、自動遷移・他roomの進捗連携はありません。

画面最上部とフッターのバージョンはpackage.jsonからビルド時に埋め込みます。日本語・英語・タイ語、オンライン版・単体HTMLで同じ番号を表示します。

各既存ケースの「演習前に読める基礎」に確認1問を設けています。任意で、回答前から使え、正誤と一般的な説明を表示します。確認結果はケース別に保存しますが、既存の設問・完了条件・卒業条件には算入しません。上部の「学習の目安（順番は自由）」も任意です。
