# 演習の追加・修正

ケースの定義は `src/cases.js` と `src/cases-extra.js`、前提と解説は `src/case-context.js`、追加の技術解説・参考資料は `src/case-reading-a.js` と `src/case-reading-b.js` にあります。既存ケースを一つ選び、同じ構造で作ると画面と連携できます。

## ケースに含めるもの

| 項目 | 内容 |
| --- | --- |
| `id` | ケース固有のID。公開後に変えると保存済みの進捗と対応しなくなる |
| `title`・`summary`・`level`・`minutes` | 題材、難易度、目安時間 |
| `initialCommand`・`briefing` | 最初に確認するコマンドと調査依頼 |
| `baselineFiles` | 正常時の仮想ファイル。絶対パスをキー、内容を文字列で定義 |
| `files` | 攻撃後の仮想ファイル一式。差分だけではなく完全な内容を定義 |
| `attack`・`logPaths` | 攻撃ボタンの説明と、調査対象のログパス |
| `tasks` | 設問、正解、許容する別解、ヒント、説明、証拠 |
| `walkthrough` | 調査に使うコマンドと、読み取れる内容 |
| `context` | 状況・目的・構成・ネットワーク・正常動作・時間範囲・ログの限界 |
| `debrief` | 技術知識、観測の流れ、原因、確認できた影響、未確認事項、対策、歴史事例、参考資料 |

`src/app.js`は選択したケースの正常ログから開始し、攻撃ボタンで `files` に切り替えます。入門モードでは正常ログのコピーを `/baseline` 以下に配置します。実践モードでは配置しません。作成したケースを `globalThis.LOG_LAB_CASES` に追加し、必要に応じてケース名の短縮表示も更新してください。

## 設問の作り方

各設問にはケース内で重複しない `id`、表示名の `label`、質問文の `prompt`、正解の `answer`、`explanation`、`hints`を用意します。別形式の解答を許容する場合は `accepted` に文字列を追加します。判定は文字列の前後の空白、連続空白、大文字小文字を正規化します。単位や表記を設問で指定すると迷いが減ります。

根拠の `evidence` は `{path, line, quote}` の配列です。`line`は1から数え、`quote`はその行と完全一致させます。解説から該当行を表示するコマンドを入力できるので、ログを変更したら行番号も見直してください。

正解の文字列を読み比べるだけの検証にせず、ログから抽出・集計・時刻差の計算などを独立に行うテストを追加します。複数ログの照合を問う場合は、request ID、ユーザー、時刻、処理結果などがつながることも検証してください。

## データと解説

- 実ログや秘密情報を使わず、教材用のIPアドレス・ドメイン・ユーザー名を使います。
- 各ログの時刻形式・年・タイムゾーンをREADME、`clockNote`、解説に明記します。異なるTZの同時刻イベントはUTCへ換算して照合し、年・TZを省いた時刻を無条件に比較しないでください。
- 正常動作も含め、攻撃と断定できる根拠と、推測に留まる部分を分けます。HTTP 200だけでは侵害成功や情報流出は確定しません。
- 攻撃後にログが削除・改変されるケースでは、独立した収集先や監査ログとの関係を説明します。「攻撃後の行数が必ず増える」という前提にはしません。
- 歴史的事案には一次資料を付け、教材との共通点と相違点を明記します。第三者の記事やログを丸ごと転載しません。
- 参考資料はHTTPSの公開URLを使います。外部URLのデータを実行時に取得する機能は追加しません。

## 変更後の確認

```sh
npm run build
npm test
npm run test:browser
```

新しいケースを増やす場合は、テスト内のケース数・設問数、画面確認、READMEと[演習一覧](EXERCISES.md)、参考資料一覧を更新します。`id`や正解を変更した場合は、保存済み状態での見え方も確認してください。公開後の利用者のlocalStorageは、ソースを更新しても自動では消去されません。

参考資料一覧は `npm run docs` で解説のデータから再生成できます。

設問や解説を追加・変更したら、`src/locales/cases-a.js`〜`cases-c.js`の英語・タイ語も更新します。同じケースID・設問ID・配列の順序を使い、ログ、正解、証拠、URL、実行コマンドは共通のままにします。翻訳カバレッジと3言語を行き来するブラウザ検証も実行してください。
